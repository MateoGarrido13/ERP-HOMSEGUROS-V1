### ADR-015: Múltiples planes por proveedor y selección de múltiples compañías en el multicotizador

**Estado:** Aceptado  
**Fecha:** 13 de Noviembre de 2026  
**Arraigado en:** ADR-002 (Aggregator + ACL), ADR-004 (Supabase + Edge Functions), ADR-012 (marcador de estimado), ADR-014 (Mercantil Andina como ACL)

---

## Contexto y Planteamiento del Problema

El usuario (PAS) necesita recibir más de una alternativa de cotización por compañía, para comparar cobertura y precio antes de seleccionar. La API de Mercantil Andina devuelve un array `resultado[]` con varios planes (ej. A, B, B0, B1, B3, M BASICA, M PLUS), cada uno con su propia prima y detalles.

Además, las demás compañías (Sancor Seguros y futuras) estarán mockeadas inicialmente con precio "No disponible", y en el futuro se deberá permitir seleccionar alternativas de más de una compañía simultáneamente (ej. plan A de Mercantil Andina + plan A de Sancor Seguros).

¿Cómo modela el ACL y el orquestador la devolución de múltiples planes por proveedor, y cómo se distinguen las cotizaciones reales de las mockeadas?

---

## Impulsores de la Decisión (Decision Drivers)

* **Múltiples alternativas por compañía:** el PAS debe ver varios planes de la misma aseguradora, no solo uno.
* **Selección mínima uno:** el PAS selecciona al menos un plan de entre todos los ofrecidos.
* **Compañías mockeadas:** Sancor Seguros y otras compañías sin API real integrada devuelven precio "No disponible" con marcador `estimado: true`.
* **Selección de múltiples compañías:** en el futuro se podrá combinar planes de distintas aseguradoras en una misma cotización comparativa.
* **ADR-012:** cualquier cotización de stub/mock/esqueleto debe llevar `estimado: true`; las de aseguradora real llevan `estimado: false` (o lo omiten).
* **ADR-002:** cada ACL es aislada por proveedor y traduce al modelo canónico.

---

## Opciones Consideradas

1. **El ACL devuelve un único `CotizacionCanonica` por proveedor** (estado actual del prompt 06). El orquestador aplanaría solo uno por proveedor. Rechazado: no permite mostrar múltiples planes de la misma aseguradora.
2. **El ACL devuelve `Promise<CotizacionCanonica[]>` (array de planes)**. El orquestador hace `Promise.allSettled` y flatten del array resultante. Aceptado: permite N planes por proveedor y combinación futura de múltiples compañías.
3. **El front recibe todos los planes y filtra localmente.** Rechazado: el modelo canónico debe ser la fuente de verdad; el front no debería conocer la estructura wire de cada aseguradora.

---

## Decisión Tomada

Se adopta la **Opción 2**.

### Cambios al modelo canónico (`supabase/functions/_shared/types.ts`)

`CotizacionCanonica` incorpora el campo `estimado: boolean` (ADR-012):

```typescript
interface CotizacionCanonica {
  proveedorId: string;
  prima: number;          // en ARS; 0 si "No disponible" (mockeado)
  moneda: "ARS" | "USD";
  cobertura: string;      // descripción normalizada del plan
  vigenciaDesde: string;  // ISO 8601
  vigenciaHasta: string;
  urlDetalle?: string;
  error?: string;         // presente si el proveedor falló o es "No disponible"
  estimado: boolean;      // true si es stub/mock/esqueleto; false si es aseguradora real
}
```

`IProveedorACL.cotizar` cambia su firma para devolver múltiples planes:

```typescript
interface IProveedorACL {
  cotizar(solicitud: SolicitudCotizacion, signal: AbortSignal): Promise<CotizacionCanonica[]>;
}
```

### Comportamiento por compañía

| Compañía | Origen | `estimado` | `prima` | `error` |
|----------|--------|------------|---------|---------|
| Mercantil Andina | API real (`/cotizaciones/v2/auto`) | `false` | Prima real del plan | `undefined` si éxito |
| Sancor Seguros | Mock/stub (no hay API real) | `true` | `0` | `"No disponible"` |
| Futuras compañías | Mock/stub hasta integrar API real | `true` | `0` | `"No disponible"` |

### Comportamiento del orquestador

`Orquestador.cotizarEnParalelo(solicitud)`:

1. Llama `proveedor.cotizar(solicitud, signal)` para cada `IProveedorACL` en paralelo (`Promise.allSettled`).
2. Cada proveedor devuelve un `CotizacionCanonica[]` (puede ser vacío si falló).
3. Aplana (flat) todos los arrays en un solo `CotizacionCanonica[]`.
4. Si un proveedor falla completamente, devuelve un solo elemento con `proveedorId`, `prima: 0`, `error` = mensaje, `estimado: true` (degradación graceful).

### Selección en UI

La UI (front) recibe el array plano de `CotizacionCanonica[]`, agrupa por `proveedorId` para mostrar alternativas por compañía, y el PAS selecciona uno o más planes mínimamente uno.

---

## Consecuencias Positivas

* El PAS ve múltiples planes por compañía (ej. plan A, B, B3 de Mercantil Andina).
* Las compañías mockeadas se identifican claramente con `estimado: true` y `error: "No disponible"`.
* Queda habilitada la selección futura de múltiples compañías sin cambiar el modelo canónico.
* Cada ACL sigue aislada (cero código compartido entre proveedores).
* Cumple ADR-012 (marcador de estimado) y ADR-002 (ACL por proveedor).

### Consecuencias Negativas

* `IProveedorACL.cotizar` cambia de `Promise<CotizacionCanonica>` a `Promise<CotizacionCanonica[]>`; todos los ACLs existentes deben adaptarse.
* El orquestador debe aplanar arrays anidados.
* El front debe agrupar por `proveedorId` para la presentación.
